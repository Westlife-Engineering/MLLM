# BLIP-2：冻住视觉模型和语言模型，只训一个桥

- 论文：BLIP-2: Bootstrapping Language-Image Pre-training with Frozen Image Encoders and Large Language Models
- 作者：Junnan Li、Dongxu Li、Silvio Savarese、Steven Hoi，Salesforce Research
- 发表：ICML 2023
- 预印本：arXiv:2301.12597
- 对应 PDF：`2023-ICML-BLIP-2.pdf`
- 阅读顺序：本目录第 3 篇。先读 CLIP 和 Flamingo。

## 先读这一段

Flamingo 证明了“强语言模型 + 视觉条件”能做少样本图文生成，但要在语言模型内部插入并训练大量新层，还要自己准备十亿级交错数据。BLIP-2 把这件事收成一个可复用的配方：视觉编码器拿现成的，语言模型拿现成的，两边全程冻结，只训练中间一个 1.88 亿参数的 Querying Transformer（Q-Former）。

零样本 VQAv2 上，它比 Flamingo-80B 高 8.7 个点，可训练参数大约少 54 倍。从这篇开始，“先对齐视觉表示，再让冻结的语言模型把字说出来”成为开源多模态模型的默认骨架。

## 它在解决什么

端到端重训一个大视觉模型和一个大语言模型太贵，也容易把单模态模型里已经有的知识训掉。只冻结一边又不够：Frozen 那条线微调视觉编码器，把图像特征直接当软提示；Flamingo 冻结语言模型，但新层很重。两边同时冻结时，模态之间的缝特别大，因为语言模型预训练时从没见过图像。作者认为，只靠“看图生成文字”这一个损失，填不上这条缝。

## 核心做法

Q-Former 是一个从 BERT-base 初始化的轻量 Transformer，大约 1.88 亿参数。交叉注意力层是随机初始化的。它有 32 个可学习 query，每个 768 维。这些 query 彼此做自注意力，并且隔层用交叉注意力去读冻结视觉编码器的特征。输出是 32×768，远小于例如 ViT-L/14 的 257×1024。这个瓶颈迫使 query 只留下和文字有关的视觉信息。

预训练分两段，都在图文对上做。

第一段，只接冻结的图像编码器，不接大语言模型。三个损失一起训，差别在 query 和文字之间的注意力掩码：

- 图文对比（ITC）：query 和文字互不可见，从 32 个 query 里取和文字最像的那个作为图文相似度。因为编码器是冻住的，显存更省，负样本直接用 batch 内的其他样本。
- 图文匹配（ITM）：query 和文字彼此可见，判断这对图文是不是真配，并用难负样本。
- 图像条件下的文本生成（ITG）：query 之间可见，但看不见文字；每个文字 token 能看见全部 query 和它前面的字。文字要能生成出来，所需信息必须先被 query 从图像里抽走。

第二段，把 query 的输出接到一个冻结的大语言模型上，作为视觉前缀，用语言建模损失训练 Q-Former。语言模型用 OPT 或 FlanT5。这一段让“query 抽出来的东西”落在语言模型已经能读的表示附近。

图像编码器是现成的 CLIP ViT-L/14 或 EVA ViT-g，不更新。所以 CLIP 在这条流水线里的角色已经从“整个模型”变成“眼睛”。

接上 FlanT5 之后，模型可以按自然语言指令做零样本图到文：视觉问答、看图对话、带知识的推理。这些能力来自冻结语言模型本身，Q-Former 负责把图送进去。

## 可以先跳过

- 各个数据集上微调和零样本的完整大表。知道 VQA、描述、检索三条都覆盖了即可。
- OPT 和 FlanT5 谁在哪个任务上更好的逐项对比。结论是这个桥可以换不同的冻结语言模型，而且指令调过的语言模型更好听话。

## 读完应留下的判断

BLIP-2 的贡献是训练配方和接口，不是一个新的视觉骨干。32 个 query 很省，也会丢掉空间细节，所以它强在“说得对、接得上语言模型”，弱在细粒度定位。视觉编码器完全冻结，眼睛的能力不会在这一阶段变强。

下一篇把桥再简化成一个线性层，把研究重心从“怎么接”转到“用什么对话数据来教模型听话”。
