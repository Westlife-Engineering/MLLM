# Auto Research：有边界的自主研究

规则入口：[[AGENTS#Auto Research 与多 Agent 协作|AGENTS · 自主研究]]。本流程调度 Ingest / Query / Brainstorm / Lint；是文献研究协议，不是后台服务。创建本库和规则不自动启动探索轮次、实验、训练或定时任务。

## 一轮的约定

用户明确启动后，从已有索引和主题整理目标/探索或聚焦模式、选定范围、候选/正文/补读数量边界、讨论轮数、写入范围、资源与并发、停止条件和交付。采用该轮实际约定，不沿用参考库的固定篇数与轮数。预算为上限，允许更少或零个新 idea；只在用户给出或环境确实提供时记录 token/时间额度，不虚报。

已有授权内自主选择和修补，不逐篇请求许可。新增论文身份先排重，跨方向一篇只计一次；补读记清工作量。范围外建议列出不执行，不无限追引文。初始迁移限定 31 个既有独立材料工作对象的补源与读取，两综述/92 页讲义另读；不能借 Auto Research 规则扩展该任务。

实际启动时才建 `maintenance/research/<轮次>.md`，记录范围、候选/排除理由、身份/URL/全文状态、ID/所有权、进度、审查与恢复点。知识页保留研究结果，日志保留完成的实质变化，不复制队列。

## 从问题选择来源

先读相关主题和已读综述/讲义的具体章节，明确希望澄清的机制、前提、对照或反例。引用只是候选线索，需核对作者/官方/会议或预印本渠道的身份、版本和全文。用户限定引用范围时严格遵从；未限定且已授权查新时，可在本轮边界内追索近义机制与新工作。筛选和元数据核对不算正文摄入。

纯官方网页按实际类型纳入，不伪装成论文凑数量。来源选择说明它能澄清什么，不能只因新、热或目录缺页。无法获取某篇时记录阻塞，尝试合法公开版本或范围内替代，不妨碍其他独立任务。

## 派发与共享写入

主 Agent 负责总协调、统一 ID/身份/路径所有权、验收和 Git。角色的模型与推理配置按本库约定执行：

| 角色 | 模型 / 推理 | 工作 |
| --- | --- | --- |
| A 来源核验 | `gpt-6-astra` / high | 核对身份、版本、一手渠道与附件关系，返回可核证据 |
| B 原件迁移 | `gpt-6.1-sol` / high | 基线清点、字节保全、完整包迁移、逐文件映射 |
| C 规则与工具 | `gpt-6-astra` / high | Schema 与最小检查工具，规则一致性和可验证接口 |
| D 单篇精读 | `gpt-6-astra` / high | 实际原文读取、唯一来源页、证据定位与返工 |
| E 跨来源综合 | `gpt-6.1-sol` / high | 共同问题下的比较、主题整合与交叉引用 |
| F 表达与图解 | `gpt-6.1-sol` / high | 阅读结构、图表表达、图源与导出同步 |
| G 独立学术审查 | `gpt-6-astra` / high | 回读关键原页、反证、证据等级和可比性审查 |
| H 结构验收 | `gpt-6-astra` / high | 原件哈希、身份计数、路径/索引/链接/状态与交付核对 |

最多同时运行 3 个 subagent，且受实际可用上限约束，预留主 Agent；按空位派发，不层层建负责人。子代理不得自行再派发。用户指定模型与推理配置不可静默降级；工具不可用如实说明并在已允许范围推进。

派发包含任务问题、必要规则、当前证据版本、身份/来源 ID、材料类型、主/交叉方向、原件与唯一页路径、可写文件、边界和交付要求。G 的关键审查尽量由未参与该主张写作的人承担；“独立”表示初稿隔离，不保证模型偏差独立。

1. 每个文件同一时刻只有一名写者。并行可读原文和写各自获分配私有页；同身份跨向复用，不重复派发/计数。
2. 单篇完成返回待整合要点与共享目标，状态 integrating。主 Agent 在全库范围授予共享写入时段，主题/索引/日志/登记表都在同一队列。
3. 获时段后重读最新文件，再整合和局部检查；不得以旧副本覆盖新内容。提交日志草稿，状态 reviewing，释放所有权。
4. G 核查重要学术主张，H 检查结构；有问题回原负责者返工，主 Agent 终审。通过后再取得短时段收尾日志与 complete 状态，返回确认。
5. 中断先确认原写者停止，再移交所有权并读取最新持久状态。未整合/未审核不算完成。这是调度纪律，不声称已有文件锁。

不协同的两个聊天不能各自充当总协调者共享同一路径写权限；桌面如有明确授权也仅能统一串行控制。

## 运行与停止

盘点和选文后逐篇摄入，按问题/机制/前提/评测条件作方向内综合。需要构思时固定共同证据，按 [[workflows/brainstorm|Brainstorm]] 独立分析、互评、定向核查和修订。跨模块结果比较接口与归因条件，不把分类当独立证明；同源引用只算一条证据。

目标已回答、已有工作覆盖候选、全文不可达、预算用尽或没有剩余可执行核查时收束并记录理由；中断诚实保留进度，不包装成完成。达到约定讨论轮数只整合已有判断，不通过新增角色重置额度。结束不自动再开下一轮。

交付知识变化、保留/关闭的问题、反证、建议亲读的原页、检查结果和未完成项。内容回唯一来源/主题，状态回维护记录，目录与表达按需同步；不倾倒全部 Agent 聊天。

## Git 与收尾

仅主 Agent 操作 Git，先查分支/HEAD/已有修改；按实际任务在规则形成、验收批次、综合与收尾建立必要本地检查点。提交期间暂停相关共享写入，核对 diff、哈希与暂存字节，显式暂存本轮文件。Raw 禁止换行转换，原件字节不变；不盲目 `git add .`、不自动 push、不重写历史、不覆盖用户修改。提交不能替代验收。

系统临时目录存可再生材料。完成后仅清理本任务临时文件，保留用户原始输入、全部已归档原件和冻结包；失败保留最小恢复集。只要求规则修订时不擅自开研究轮次或迁移资料。
