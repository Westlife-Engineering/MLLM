# Brainstorm：围绕共同证据独立提出和审查问题

规则入口：[[AGENTS#Auto Research 与多 Agent 协作|协作规则]]。由 Query 或已授权的 Auto Research 调用，目标是澄清、提出可调查的问题或关闭误判，允许零个新 idea，不自动启动实验。

## 先完成证据准备

固定问题、范围、当轮讨论/补读边界，以及来源 ID、版本/哈希、实际读取范围、唯一页和原始定位。列已知机制、前提、条件、冲突、未知和相关反例，不只给正面结果。区分原文、综述/讲义转述、推断和待检验问题，冻结旧笔记与对话只能提供线索。

证据包引用正式来源，不复制平行正文；临时证据包放系统临时目录，持久短版本与审查范围放维护记录。讨论中证据变化须同步给所有参与者；缺乏直接原文时只能形成补读问题，不能宣称研究缺口。

## 综述或讲义内讨论与组会交付

用户限定材料时，明确章节/页段和是否允许检索、追引文、其他章节或新增来源；未授权的扩展不执行。可跨章节归纳关系，但材料没提到不证明领域空白。

组会任务在活动 README 记录材料、角色、边界、写入范围和交付，原始用户提示完整保留。归纳注明连接的具体页段与推理；假设注明尚待检验。洞见要能说明改变某个前提会怎样改变设计选择、最强反例能否推翻解释，不能只说“融合模块”或依赖角色共识。

完整讨论定稿、结构化首稿和关键修订作为形成过程保留；主 Agent 回读最终主张原页，再把可独立理解的成果写回正式主题，两处互链。未经核验的候选留活动记录，不自动升级到已验证知识。遵从 [[workflows/structure#组会工作区与成果沉淀|工作区规则]]。

## 独立分析、互评与修订

角色和模型按 [[workflows/autoresearch#派发与共享写入|角色表]]；E 负责跨来源构思/综合，G 负责机制边界与反证审查，D 可承担必要原页补读，主 Agent 组织和终审。只派当前任务必要角色，最多 3 subagent 并发，子代理不再派发。

首轮只提供共同证据和约束，不传其他初稿或预设答案。独立任务不表示偏差独立。先收齐判断再交换，保留分歧；关键质疑转成具体原页核查、近义机制检索或预算内补读，不能用措辞辩论替代证据。后续将同一增量证据发给参与者，说明原判断为何改变及问题状态。

讨论轮数、候选数和补读数量采用当轮约定，没有固定历史配额；无新证据且无剩余具体核查时提前停止，达到上限即收束，不以新增角色或跨模块重置额度。顺序执行可以隔离首稿，但已看过其他答案的任务不能称独立首轮。

关键主张由未参与写作的审查者回原页，给“支持 / 部分支持 / 不支持 / 无法判断”和定位。主 Agent 不用投票、角色头衔或模型评分确认学术结论；一篇来源被多人引用仍是一篇。

## 候选问题的最小内容

区分理解缺口、本库证据缺口、限定检索范围内候选研究缺口；“本文没做”不是“领域没人做”。有长期价值的问题写入最合适主题页，成熟后才拆页，每项应能回答：

| 内容 | 要回答什么 |
| --- | --- |
| 问题与范围 | 哪个具体任务、条件或机制值得弄清？ |
| 引出证据 | 哪些已读来源的哪些原页支持提问？转述另标 |
| 解释与推理 | 观察怎样导出候选解释，哪些步骤仅属推断？ |
| 最接近工作 | 已核读机制/条件/任务覆盖多少，剩余区别是什么？ |
| 最强反对意见 | 哪条反例、归因混杂或失效前提会推翻它？ |
| 下一条证据 | 哪个补读、核查、消融或失败案例可区分解释？仅提出，不自动实验 |
| 状态与理由 | 待澄清、待补读、待查新、继续追踪、已有工作覆盖或暂缓 |

被覆盖的问题保留简短关闭理由，避免反复提出；继续追踪不代表创新性、可行性或最终选题确认。

## 查新与写回

仅在范围内执行检索，记录日期、渠道、实际词/近义词、覆盖范围、相关结果、全文可用性和已核读范围。围绕机制、任务和失败现象，不只搜 MLLM 标签。摘要和搜索结果是线索，关闭/保留候选的关键判断仍须回正文。表述限于已核查材料和条件，查不到不是不存在；只检索综述引用时明确不是覆盖后续文献的查新。

单篇修正回唯一来源页，跨来源关系和问题回主题，Overview 留导航。共享写前重读，主 Agent 验收并运行 Lint 与受影响的表达检查；实质综合合并记 query 日志。过程状态归维护记录，原始用户输入保留；临时长检索输出和重复草稿只按本任务临时清理规则处理。
