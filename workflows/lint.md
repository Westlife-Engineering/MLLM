# Lint 清单

规则入口：[[AGENTS#6. Lint：结构与证据健康检查|AGENTS · Lint]]。每次局部更新检查受影响范围；迁移、大结构变更和独立维护做全库检查。

## 只读检查工具入口

从 Vault 根目录运行 [检查脚本](../scripts/check_vault.py)，默认检查脚本所在的库；测试其他目录可显式传 `--root <目录>`。使用已有的 Python 3.11 或更新环境，以及已安装的 PyYAML（`yaml`）和 PyMuPDF（`fitz`）；不要为例行检查自动安装或更新全局环境。`-B` 避免生成新的 Python 字节码缓存，脚本本身不写文件、不联网、不操作 Git、不编译 TeX。

```text
python -B scripts/check_vault.py
```

上述默认模式是严格结构检查（strict）。脚本向标准输出返回 JSON，包含 `errors`、`warnings`、计数、已登记历史断链及 `passed`；无错误退出码为 0，有错误为 1。依赖缺失或程序无法启动也可能非零退出，不能把缺少有效 JSON 报告当作通过。

检查器还读取 [[workflows/taxonomy.yaml|方向词表]]，核对主/交叉方向与导航入口；沿 `raw_moves` 校验多跳字节链，将 `wiki_moves` 与 Raw 清单分开。只有显式冻结并哈希吻合的历史维护文档及追加日志可追溯旧链接，当前 Wiki/规则继续严格使用现路径。历史 Wiki 追溯核同一来源 ID 的当前唯一页，检查点哈希不冻结其未来正文；解析后继续检查锚点/PDF页码。

用户明确撤下的文档可在迁移清单的 `withdrawn_documents` 登记原路径、删除前大小/哈希、日期、授权原话、原因和保留的维护入口。检查器仅允许追加日志与已冻结历史文档沿该登记追溯；当前链接仍严格。该登记不豁免 Raw 集合或来源原件检查；用户明确删除本轮尚未提交的新原件时，原归档条目改记撤下历史，不再计入当前原件集合。

`topic_reference_candidates` 是去掉 frontmatter/页末入口后的正文 Raw 引用与 registry 登记差集，供人工判断；它不进入 errors/warnings，不自动补实质关系。`registered_integrated_relations` 是已登记数，`manifest_raw_records` 是原件登记条数，`raw_path_moves` 是路径移动条数，均不能互相代替。检查器不判定关系贡献深度或归属理由的学术正确性。

建设过程中可运行：

```text
python -B scripts/check_vault.py --allow-incomplete
```

施工模式只将未完成来源的待建页面、索引暂缺及索引覆盖遗漏列为 warning；已经标记 complete 的来源页缺失仍是错误。它不放宽原件哈希/大小、实际断链、非法 PDF 页码、已有页面状态与 registry 不一致等问题。最终结构验收必须去掉 `--allow-incomplete`，不能用施工模式通过替代 strict。

检查器修改后的回归测试入口为 [临时样例测试](../tests/test_check_vault.py)：

```text
python -B -m unittest discover -s tests -v
```

测试使用临时目录构造正负样例；测试数量随覆盖需要变化，不作为固定验收配额。仅调整本清单等低影响文档时，核对相关链接和命令事实即可，不机械重复全套测试。

strict 通过只表明本次快照满足脚本已实现的结构条件；它不要求所有来源都已 complete，也不证明学术判断正确、约定阅读与整合全部完成、图像实际渲染正确或 Obsidian 显示通过。最终任务完成仍须对照本轮范围、来源状态及独立审核结果。TeX 检查属于静态资源检查，不代替编译；HTML 远程资源也不因此成为完整离线存档。

## 检查清单

| 检查 | 通过条件 | 处置 |
| --- | --- | --- |
| 原件完整 | 全部用户输入可追踪；存在、大小与 SHA-256 一致；旧包内部结构不变 | 报告差异，不能改哈希掩盖或修改原件 |
| 身份核验 | 标题、作者、标识符/官方出处、版本有实际核对；哈希不替代身份 | 不确定字段明确未确认，错配必须纠正 |
| 材料归属 | surveys / papers / lectures / notes / web / code / articles 分流；生成记录不在 Raw | 按映射迁移，保留原件，不自动精简 |
| 来源唯一性 | survey / paper / lecture / source 递归按身份查重；ID 唯一且不回收 | 核对同论文版本、附件、InternViT 与 V4.1 多总结关系 |
| 主归属/镜像 | paper / source 的 primary_direction 与目录一致，论文 PDF/页简称镜像，HTML 例外有登记 | 修正或按迁移协议处理，不复制跨方向来源 |
| 状态 | reading_status / ingest_status 与实际读取、整合、验收一致 | 降级虚高状态；下载不等于读完，文件生成不等于完成 |
| 计数 | 文件、工作对象、去重学术来源、其他来源分别登记 | 不用文件数量充当论文数量；不把引用文献算已读 |
| Frontmatter | 知识页有 type / created / updated / sources；来源页有统一三字段 | 补事实字段，不能以占位内容造假 |
| 链接/定位 | 当前链接和标题/块锚点存在，PDF 页码在实际范围；HTML 定位真实 | 修正路径/锚点，不能以搜索摘要代正文 |
| 索引与关系 | 所有知识页有索引链接/摘要；真实主题整合有双向链接 | 补漏；维护记录/图源不当知识页计数 |
| 文件树 | 主方向可浏览，无空页/空目录、意外平铺或 wiki 嵌套副本 | 标明实际缺陷，不以索引可达替代目录验收 |
| 证据等级 | 原文、转述、推断、问题清楚；旧笔记不是论文原文 | 回原页核查或降低表述强度 |
| 论文理解 | 困难、机制、前提、证据范围、局限与本库影响清楚 | 定向返工，不填模板或强凑 gap |
| 可比性 | 数据/模型/分辨率/token/预算/指标/评测协议等相关条件明确 | 不可比分数不排名，冲突保留条件差异 |
| 讲义质量 | 原 PDF 直接核读，重要概念有页段，公式/图/例在概念中解释，补充另标 | 不把目录扫描冒充全文理解 |
| 语义与查新 | 术语一致，冲突和未知可见，研究问题有反证与检索范围 | 不将“没找到/本文没做”写成无人做过 |
| 多 Agent | 正确模型/推理、最多 3 sub、单写者、共享写前重读、主 Agent 统一 ID | 修复并发覆盖，独立审查不以角色投票代证据 |
| 任务边界 | 当前范围、停止条件和补读额度可回查 | 不自动开下一轮/实验/定时任务 |
| 图文与语法 | 图不升级证据，箭头含义清楚；表格别名转义，公式/Mermaid/Callout 结构有效 | 同步正文、图源和导出，退出过时主入口 |
| 阅读结构 | Overview 是地图，主题有实质解释，无平行长正文/队列堆积 | 搬移内容并更新入链，过程记录归维护 |
| 应用验收 | 只报告实测条件；文件/渲染/Obsidian 明确区分 | 未获授权不操作桌面；未实测如实标记 |
| 维护与历史 | 日期真实、日志只追加、迁移映射完整 | 追加更正，当前链接不用历史例外免责 |
| 临时区 | 只清本任务可再生材料，中断恢复集有用途；原件不自动清理 | 不跨任务、不以 Git 忽略当清理、不删旧包 |

可确定的链接、索引和格式可自动修复；学术语义须回证，无法解决留待核查。一次更新附带检查并入操作日志；独立全库检查或重要异常才另记 lint。脚本成功仅证明覆盖的结构检查，人工语义审查与原页回读不可省。

迁移验收按 [[workflows/structure#已有目录的迁移协议|迁移协议]] 核对映射、原件字节、身份/ID、各类数量和当前引用。已说明的历史路径只有目标存在且哈希匹配才列例外；冻结原件内部引用不自动改写。当前 Wiki 与索引的意外断链仍属错误。用户撤下的非 Raw 资产需有追加记录，不能自动重建。

图文检查按 [[workflows/presentation|阅读表达]]，分别交付结构报告、学术核验范围、已看的图和应用实测条件；无法访问 Obsidian 不影响执行其余检查，但不能称全部展示验收通过。检查工具实现应递归识别全部来源类型，不硬编码本轮文件总数、页数或来源数量作为长期真理。
