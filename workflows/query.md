# Query 清单

规则入口：[[AGENTS#5. Query：有证据地回答并积累|AGENTS · Query]]。用户提问或已授权的文献研究轮次均可触发。

1. 从索引与相关主题定位，再读唯一来源页；递归覆盖综述、论文、讲义与官方文档，不凭旧文件名重造来源。
2. 回读关键原文及条件，核实版本和实际阅读范围。综述/讲义引用与冻结旧总结均不能当作原论文已读证据。
3. 按问题回答，主张紧邻原页或 HTML 定位，区分原文、转述、本库推断和待检验问题。需要新增来源时先核对任务范围，再接 [[workflows/ingest|Ingest]]；初始 31 工作对象的补源不自动扩展到综述/讲义引用链。
4. 持久综合、比较、纠错或问题写回合适现有主题。Overview 妨碍定位且已有实质内容时搬移拆页、保留导航；没有新知识不造页。[[workflows/presentation|图文表达]] 按解释需要选用，普通短问答不强制图解。
5. 按需同步日期、索引、交叉引用和图，做局部 [[workflows/lint|Lint]]。只有持久认识、重要问题、实质纠错才合并记 query 日志；普通说明与轻微修订不记。用户要求只回答时不落盘。

查询和对话结果不是新论文证据，再引用仍回原始来源。用户明确要求基于聊天更新笔记时使用 [[conversation-to-note/SKILL|conversation-to-note]]，核对完整相关轮次与当前文件，不能根据旧审核声明认定现稿已通过。

检索技术机制时先用方向/主题入口；检索家族、版本或组件时用 [[wiki/models/Overview#家族与组件导航|跨方向家族导航]]，仍回同一来源页。任务、输入输出和训练/部署阶段在相关机制页核对：caption、坐标串、视觉表示与合成图像不可共用一个“生成”标签。综述/讲义的覆盖地图只说明实际读到的转述，不自动新增被引论文身份。对查询产生的持久使用，按 Ingest 的关系判据判断是否补 `integrated_topics`，不按链接数量登记。

## 跨来源综合

围绕共同问题比较具体困难、改变对象、信息流、前提、任务/数据/模型/分辨率/token/预算/指标和证据覆盖。首先判断结果是否可比较，再解释共同机制、条件差异、表面冲突和缺失消融；不堆摘要、不排不可比分数榜。官方声明与论文结果、讲义解释与原始发现必须保留不同身份。

交付说明原判断、改变它的证据、仍有的分歧和下一条可获得的证据。区分理解缺口、本库证据缺口、限定查新范围内的候选研究缺口；零个新 idea 或关闭误判问题都是有效结果。有需要时调用 [[workflows/brainstorm|Brainstorm]] 固定共同证据、隔离首稿、互评和定向回读，模型共识不增加证据。

## 组会型讨论

用户要求组会成果时，按 [[workflows/structure#组会工作区与成果沉淀|活动工作区]] 保留原始输入、定稿讨论、结构化提案和关键修订，Wiki 接收经核查且可独立阅读的理解，两处互链。只读综述/讲义的约束同样适用于概述与图解，不自动查新、追引用或实验。

主 Agent 审核共享写入；原负责者修订单篇解释，学术疑点由独立审查者核对原页。内容、文件/结构、独立渲染和 Obsidian 实测分别报告，未测如实说明。
