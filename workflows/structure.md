# 目录组织与迁移

规则入口：[[AGENTS#1. 三层边界|三层边界]]。所有任务共用本清单，不另定平行路径。

## 材料按类型归档

| 内容 | 目标位置 | 边界 |
| --- | --- | --- |
| 综述原文 | `raw/surveys/<简称>.pdf` | 真实综述版本；HTML 原始渠道走 web，不伪造 PDF |
| 论文/学术报告原文 | `raw/papers/<模块>/<方向>/<简称>.pdf` | 按已核验身份归档；不同版本另存，正文内附录不拆 |
| 课程讲义 | `raw/lectures/<原文件名>.pdf` | 保留课程材料身份和实际页数，不升级为所引论文原文 |
| 旧笔记包 | `raw/notes/<原包>/` | 完整保留内部目录、TeX/PDF/Markdown、图片、样式、附件与相对路径，冻结字节 |
| 网页原件 | `raw/web/<来源ID>-<简称>/` | 作者/机构官方 HTML、模型卡与文档；记录 URL/日期/版本、用途及快照缺失范围 |
| 官方代码 | `raw/code/<来源ID>-<简称>/<commit>/` | 按实际核读用途保存必要源码/配置与原仓库相对路径；记录完整 commit 与读取范围 |
| 理念文章/用户输入 | `raw/articles/` | 理念材料或独立原始文本，原始输入不计学术来源；不作过程杂物目录 |
| 综述唯一页 | `wiki/surveys/<简称>.md` | `type: survey`，与 PDF 原文简称镜像 |
| 论文唯一页 | `wiki/papers/<模块>/<方向>/<简称>.md` | `type: paper`，与 PDF 原文路径镜像 |
| 讲义唯一页 | `wiki/lectures/<简称>.md` | `type: lecture`，页段、重点、概念/公式/例子保持在一起 |
| 官方文档唯一页 | `wiki/sources/<模块>/<方向>/<简称>.md` | `type: source`，不能因模型名知名就伪称论文 |
| 主题综合 | `wiki/<主题>/` 下有内容的页面 | 面向问题、机制、比较与条件，不保存完整操作队列 |

实有作者补充文件可放所属来源目录下 `<来源ID>-supplements/`，登记为附件而非新增来源；不预建目录。同一工作可有论文、官方网页与代码证据，保持清晰关系，身份/来源页是否独立以是否属于独立论证来源决定，由总协调者统一登记。只有 HTML 的论文若身份可核验，仍可有 paper 页并明确原件在 web，镜像检查记录此类型例外；纯文档则用 source。

Agent 生成的下载清单、审查报告、哈希表和检索输出不是 Raw。持久记录放 `maintenance/`；暂存下载、提取文本、渲染、脚本及草稿放系统临时目录。不得把参考库 `.research-tmp/` 历史例外当永久授权。

## 一个主归属，多个主题关系

普通论文与官方文档的 primary_direction 与目录一致；related_directions 只记录实际交叉关系。一个身份一个来源 ID、一个来源页，其他方向链接过去，不复制 PDF 或正文，不用软链接制造多份来源。来源 ID 不随迁移变化，不回收已分配编号。

| 主方向 | 初始材料归属 |
| --- | --- |
| `vision/encoders` | ViT、SoViT、NaViT、AIMv2 |
| `vision/alignment` | CLIP、SigLIP、SigLIP2 |
| `architecture/pretraining` | ALBEF、BLIP、CoCa、VLMo、BEiT-v3 |
| `architecture/connectors` | Flamingo、BLIP-2、InstructBLIP、MiniGPT-4、mPLUG-Owl |
| `architecture/generation` | MiniGPT-5 |
| `models/llava` | LLaVA 1、1.5、NeXT，对应原文身份逐一核验 |
| `models/internvl` | InternVL；同论文内 InternViT 不拆独立来源 |
| `models/qwen` | 现有 5 个独立材料对象，名称和出处由核验决定 |
| `models/deepseek` | 现有 4 个独立材料对象；V4.1 两份总结若同一报告则合并学术身份 |

该表规定初始工作对象的主方向，不预先证明其作者、版本或论文身份。新增类别须有实质内容和归属理由，同步词表，不把未确认材料长期堆到“其他”。综述和讲义单列，不强制技术主方向。

主题词表 foundations / vision / architecture / training / efficiency / reasoning / evaluation / models 与来源主目录分工不同。Overview 给地图和短摘要；子方向有独立内容且集中页妨碍定位时，搬移到明确主题页，更新入链和摘要，不保留平行长正文。不因某主题名在词表中就建空页。

## 保留标准与临时文件清理

全部用户输入和已归档 Raw 原件默认保留，不自动精简旧包、编译文件、重复总结或辅助快照。来源身份去重不等于删除文件。新获取附件以具体论据或明确复用用途决定是否归档；纯身份页面可仅登记元数据，但一旦已作为原件保留，删除需有明确适用授权。

任务结束可清理本任务生成的可再生临时材料；中断保留最小恢复集，写明用途与下一处理点。不得清理其他活动任务，不能以 Git 忽略代替清理。递归删除前解析绝对路径，核对目标属于本任务临时区、无跨界重解析点，使用同一 shell 的 LiteralPath 操作；不得按扩展名或通配符批量删 Raw。

### 组会工作区与成果沉淀

仅在实际组会任务中创建 `组会/<准备日期>-<主题>/`。README 记录范围、材料版本、角色/写入所有权和验收；保留用户原始提示、完整讨论定稿、结构化提案及关键修订，用于解释判断如何形成，不计学术来源、不要求知识页 frontmatter 或逐文件索引。临时过程材料仍用系统临时目录。正式知识页保留可独立阅读且经原页核对的成果，与活动记录互链；正式图源只在 Wiki 资产处保留一份。

## 已有目录的迁移协议

1. 盘点当前文件/Git 改动、身份、版本和工作对象，建立逐文件旧路径→新路径、SHA-256、大小、类型与关联入链映射。未判明材料列异常，不覆盖、不丢弃。
2. 迁移先取得路径所有权，暂停同范围写入；协调者按授权建立必要检查点，按包或方向小批执行。旧笔记包保留完整内部结构。
3. 原件移动前后核对 SHA-256 和大小；目标存在则核验冲突，不能覆盖。源文件字节不变化、不转码、不去重删除。所有原始用户输入应能在映射中追踪。
4. 同步可维护 Wiki、frontmatter、索引、当前规则实例和展示引用，保留 PDF 页码、标题/块锚点与表格转义。不依赖应用自动改链。
5. 原件内部引用与旧日志保持原样；迁移记录保存映射。当前 Wiki 链新路径，历史旧路径仅在映射、目标、哈希同时有效时作为已说明例外，不复制旧路径掩盖断链。
6. 递归验收文件数/字节/哈希、工作对象数、去重学术身份数和其他来源数；分别报告，任何差额有逐项解释。检查原件完整、来源唯一、镜像归属、状态、索引覆盖、链接/锚点、空目录与嵌套副本。
7. 主 Agent 审核 diff 和明确暂存范围，按用户授权本地提交；不自动 push。规则落盘不等于迁移完成，结构检查不等于阅读验收，Obsidian 未实测须明确。

所有写入路径从 Vault 根解析并验证在项目内；wikilink 的 `wiki/...` 不相对当前笔记目录拼接。参考库保持只读。
